# 장애물 AUTO / 수동 이동 제어

앱과 이 펌웨어를 함께 사용해야 합니다. 기존 신호등 제어는 유지됩니다.
장치 이름: ESP32_Obstacle_2. 보드: ESP32 Dev Module.
원본 전체 플래시 백업은 저장소에 포함하지 않습니다.

## 핀

- 모터 출력: GPIO16,17,18,19 (원본 펌웨어의 네 출력과 위상 패턴 사용)
- 왼쪽/보드 쪽 끝 스위치: GPIO27, LOW=눌림
- 오른쪽/보드 반대쪽 끝 스위치: GPIO26, LOW=눌림
- GPIO23: 외부 용도가 확인되지 않아 변경하지 않음

## 처음 업로드

1. firmware/ObstacleController/ObstacleController.ino를 Arduino IDE에서 엽니다.
2. ESP32 Dev Module과 실제 USB 포트(현재 확인된 포트는 COM3)를 선택합니다.
3. 기존 프로그램을 실행하지 않는 BOOT 다운로드 모드에서 업로드합니다.
4. 업로드는 기존 진단/실행 프로그램을 대체합니다.
5. 시리얼 모니터를 115200 baud, 줄바꿈 전송 설정으로 엽니다.
6. 전원을 켜도 자동으로 이동하지 않습니다. 초기 상태는 STOP입니다.

리셋 중 하드웨어 출력이나 미확인 드라이버의 상태는 보장하지 않습니다.
움직임/갈리는 소리가 예상과 다르면 즉시 장치 전원 스위치를 끕니다.
소프트웨어 STOP은 전원 차단형 비상정지가 아닙니다.

## 모터 방향 확인: 정상 제어는 이 단계 전까지 차단

모터가 구동될 수 있도록 주변을 비우고 이동부와 벨트에 손을 대지 마세요.
STATUS를 보내 LEFT/RIGHT 값을 확인합니다. 1=눌림, 0=해제입니다.
양쪽 스위치가 해제된 상태에서만 JOG+ 또는 JOG-가 허용됩니다.
끝 스위치가 눌려 있어 JOG가 차단되면 강제로 레버를 떼거나 이동부를 밀지 말고 현재 위치를 알려주세요.

1. JOG+를 한 번 보내면 12개 위상 스텝만 실행하고 출력이 LOW로 돌아옵니다.
2. 짧게 어느 쪽으로 움직이는지 확인합니다. 움직임을 확인하지 못하면 방향을 저장하지 마세요.
3. JOG+가 보드 쪽(왼쪽)으로 움직였다면 MAP+LEFT를 보냅니다.
4. JOG+가 보드 반대쪽(오른쪽)으로 움직였다면 MAP+RIGHT를 보냅니다.
5. READY:1 응답을 확인합니다. 방향 설정은 재부팅 후에도 저장되지만 이동 모드는 저장되지 않습니다.
6. 잘못 저장했다면 STOP 후 RESETMAP으로 방향을 지우고 다시 확인합니다.

아직 실제 모터 방향, 드라이버 동작, 이동 거리/속도는 장치에서 검증하지 않았습니다.
JOG에서도 떨리기만 한다면 시험을 중단하고 드라이버/모터 연결을 확인해야 합니다.

## 앱 사용

업데이트 APK를 휴대폰에 설치하고 장애물 연결을 누릅니다.
새 펌웨어 확인 및 READY:1 수신 후 이동 버튼이 활성화됩니다.

- AUTO 켜기: 지정한 출발 끝으로 먼저 복귀한 뒤, 출발 끝 ↔ 설정한 중간 거리 왕복. 각 전환에서 500ms 정지
- AUTO 끄기 / 정지: 출력 LOW로 정지하고 수동 입력 대기
- 좌우 버튼: 누르는 동안 해당 방향 이동, 손을 떼거나 영역을 벗어나면 정지
- 왼쪽은 보드 쪽, 오른쪽은 반대쪽
- 끝 스위치가 눌린 쪽 이동은 차단하고, 반대쪽으로 이동하는 것은 허용

처음에는 짧은 수동 조작으로 방향을 다시 확인한 다음 끝 위치 정지를 확인합니다.
방향이 맞지 않으면 AUTO를 켜지 말고 STOP / RESETMAP부터 진행합니다.

## 명령

| 명령 | 기능 |
|---|---|
| B10 | AUTO 시작 |
| B11 | 정지(AUTO 해제); 이전 펌웨어의 OFF 목적지 이동을 재현하지 않음 |
| B12 | 구동하지 않고 정지; 이전 ON 목적지가 정의되지 않아 사용하지 않음 |
| B20 | 왼쪽 수동 이동/유지 |
| B21 | 오른쪽 수동 이동/유지 |
| B22 | 정지(AUTO 해제) |
| B25 | 통신 유지; 이동을 시작하지 않음 |

시리얼 전용: STATUS / JOG+ / JOG- / MAP+LEFT / MAP+RIGHT / RESETMAP / STOP / HOMEBOARD / HOMEFAR / MIDDLE=n.
블루투스 명령은 3바이트 단위로 처리하므로 분할 수신/연속 명령/줄바꿈을 지원합니다.

## 보호 동작과 제한

- 수동 이동 명령 갱신이 600ms 동안 없으면 정지
- 연결 해제 또는 통신 유지 명령이 1500ms 동안 없으면 정지
- 한 방향 이동 3000 위상 스텝 또는 속도별 시간 한도 도달 시 보호 정지(저속 33초, 중속 21초, 고속 20초)
- 양쪽 끝 입력이 동시에 눌리면 보호 정지
- 보호 정지는 원인을 확인한 후 정지 명령으로 해제; 양쪽 입력이 계속 눌리면 다시 차단
- 전원을 다시 켜거나 앱을 다시 연결해도 자동 이동 재개 안 함

속도별 위상 간격과 시간 제한은 초기 설정입니다. 저속 10ms, 중속 6ms, 고속 4ms입니다.
실제 트랙 끝에 도달하기 전에 보호 정지가 걸리면 값을 임의로 늘리지 말고 이동 결과를 기록합니다.

## 검증

ESP32용 arduino-cli 컴파일 성공. Flutter 테스트에서 미확인 펌웨어 이동 차단,
길게 누르는 동안 명령 갱신, 손 떼기 정지, AUTO 끄기 정지, 백그라운드 정지를 확인했습니다.
실제 장치 업로드/구동 검증은 수행하지 않았습니다.


## 끝 ↔ 중간 AUTO (이번 수정)

기본 출발/복귀 위치는 모터·보드 쪽 GPIO27입니다.
AUTO를 켜면 현재 위치와 무관하게 먼저 지정한 끝 스위치까지 복귀합니다.
끝에서 0.5초 대기한 후 반대 방향으로 middleSteps만큼 이동하고,
중간에서 0.5초 대기한 후 출발 끝 스위치로 복귀합니다. 이 동작을 반복합니다.
AUTO 중 정지/수동 전환/연결 해제는 즉시 기존 자동 진행을 취소합니다.
다시 AUTO를 켜면 기준 끝을 다시 찾아 스텝 기준을 맞춥니다.

600스텝은 시험용 이동 거리이며 실제 트랙 중간을 측정한 값은 아닙니다.
스텝을 세는 방식은 모터 탈조/벨트 미끄러짐을 감지하지 못합니다.
출발 스위치는 매 복귀 때 기준을 재설정하며 반대 끝 스위치도 계속 보호합니다.
출발 후 30스텝까지도 출발 스위치가 눌려 있으면 보호 정지합니다.

설정은 앱의 정지 버튼 또는 시리얼 STOP으로 멈춘 뒤 수행합니다.
- HOMEBOARD: 모터·보드 쪽 끝 출발/복귀
- HOMEFAR: 보드 반대쪽 끝 출발/복귀
- MIDDLE=600: 출발 끝부터 600 위상 스텝 이동 후 복귀
- MIDDLE=800: 더 멀리 이동. 허용 범위는 정수 12..2400
- STATUS: AUTO_CONFIG: HOME=BOARD/FAR MIDDLE_STEPS=... 확인

HOME/MIDDLE 설정은 재시작 후에도 유지됩니다.
앱 버튼은 'AUTO 켜기 · 끝–중간 왕복'으로 변경했습니다.
교수님 폰 설치 스크립트도 같은 위치의 최신 APK를 설치합니다.
이번 코드와 앱은 빌드/앱 테스트를 확인했으며 장치 업로드는 하지 않았습니다.


## 속도 선택과 중간 거리 조정

앱의 저속/중속/고속 버튼을 정지 상태에서 선택합니다.
펌웨어가 SPEED 응답을 보내야 실제 선택값으로 표시됩니다.
AUTO/수동 이동/보호 정지 동안 속도 변경은 차단합니다. 먼저 정지하세요.
새 앱과 새 펌웨어를 모두 적용해야 속도 버튼이 활성화됩니다.
기본 중속. 위상 간격: 저속 10000us / 중속 6000us / 고속 4000us.
선택한 속도는 전원을 껐다 켜도 유지되며 AUTO와 수동에 공통 적용됩니다.
방향 확인용 JOG 속도는 6000us로 고정합니다.
B30=저속 / B31=중속 / B32=고속. 정지 상태에서만 처리합니다.
고속 실제 구동/탈조 여부는 실물 검증이 필요합니다.

중간 거리 조정(추천: 재업로드 없이 시리얼 사용):
1. 앱 정지 또는 시리얼 STOP.
2. 시리얼 모니터 115200 baud, 줄바꿈 설정.
3. MIDDLE=600, MIDDLE=700 등 전송. 숫자가 커지면 출발 끝에서 더 멀리 이동합니다.
4. 앱 AUTO를 켜서 위치를 확인. 시작할 때 출발 끝으로 먼저 복귀합니다.
5. 변경하려면 다시 STOP 후 MIDDLE=n. 허용 범위 정수 12..2400.
6. STATUS 출력 AUTO_CONFIG의 MIDDLE_STEPS로 실제 값을 확인합니다.

코드 기본값을 바꾸려면 .ino 상단 DEFAULT_MIDDLE_STEPS = 600의 숫자를 바꿉니다.
코드 수정은 다시 컴파일/업로드해야 합니다.
단, 저장된 MIDDLE=n 값이 코드 기본값보다 우선합니다.
새 코드 기본값을 적용하려면 정지 상태에서 MIDDLE=DEFAULT를 보내 저장된 설정을 지웁니다.
중간은 센서 실측이 아니라 출발 끝으로부터 위상 스텝을 세는 위치입니다.
속도 변경은 스텝 수를 바꾸지 않지만 탈조/미끄러짐이 있으면 실제 위치가 달라질 수 있습니다.
